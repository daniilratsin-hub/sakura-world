# Backend и подключение Minecraft

## Сейчас
Это безопасная стартовая заготовка, а не готовый платёжный шлюз. По умолчанию `PAYMENT_MODE=demo`: платежи не принимаются, покупки не выдаются. Не переводите режим в `live`, пока не реализована интеграция выбранного провайдера.

## Что потребуется для настоящей оплаты
1. Совершеннолетний владелец оформляет аккаунт в выбранном платёжном сервисе.
2. Добавляется серверный endpoint создания checkout-сессии, использующий сумму и товары из серверного каталога, а не из браузера.
3. Провайдер перенаправляет игрока на свою защищённую страницу оплаты.
4. Backend проверяет подпись webhook по официальной документации провайдера.
5. Проверка должна быть идемпотентной: повторное уведомление не выдаёт товар второй раз.
6. После подтверждения сервер сохраняет заказ в постоянной базе данных.
7. Только после этого заказ попадает в очередь выдачи на Minecraft-сервере.

## Связь с Paper / Spigot / Purpur
Варианты интеграции:
- отдельный Minecraft-плагин, который безопасно опрашивает backend по HTTPS;
- внутренняя очередь заданий с подписанными/аутентифицированными запросами.

Не открывайте RCON в интернет и не принимайте Minecraft-команды от пользователя. Ник и ID товара должны проходить валидацию. Секреты храните в переменных окружения.

## Перед реальным запуском
- добавить базу данных и миграции;
- реализовать конкретный платёжный провайдер и проверку webhook;
- добавить лимиты, журналы аудита и защиту от повторной выдачи;
- добавить страницу статуса заказа и понятные условия возврата;
- проверить условия провайдера и местные требования.
